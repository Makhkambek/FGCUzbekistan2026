# FGC Uzbekistan — сайт подсчёта баллов

Подсчёт по 2026 FIRST Global Challenge Game Manual (Igniting Innovation).
Публичное табло (`/`), вход и админка (`/admin`) для судей.

## Запуск

```bash
brew services start mysql

# только при первом запуске на этой базе:
mysql -u root fgc < db/schema.sql     # если базы fgc ещё нет — сначала CREATE DATABASE, см. ниже
npx tsx scripts/create-admin.ts <логин>

npm run build && npm start            # или npm run dev для разработки
```

Если базы `fgc` ещё не существует:

```bash
mysql -u root -e "CREATE DATABASE fgc CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root fgc < db/schema.sql
```

`.env.local` должен содержать `DATABASE_URL` и `SESSION_SECRET` (32+ символов) —
пример в `.env.example`. **Сервер намеренно отказывается стартовать**, если
одной из этих переменных нет или `SESSION_SECRET` короче 32 символов — раньше
это падало только при первом входе судьи в систему, то есть посреди турнира.
Лучше упасть сразу при `npm start`, чем в разгар матчей.

`create-admin.ts` **спрашивает пароль в терминале** (stdin), а не принимает его
аргументом — специально, чтобы пароль не оседал в истории шелла:

```
$ npx tsx scripts/create-admin.ts admin
Пароль:            ← вводите пароль, символы не отображаются, затем Enter
Пользователь admin создан/обновлён
```

Пароль — минимум 12 символов. Повторный запуск с тем же логином меняет пароль
существующего аккаунта (не создаёт дубликат).

Открыть: табло — `http://localhost:3000/`, админка — `http://localhost:3000/admin`.

## Доступ из зала

Узнать IP ноутбука: `ipconfig getifaddr en0`. Табло и админка открываются у
всех в той же Wi-Fi/LAN сети по адресу `http://<IP>:3000`.

Это работает по обычному HTTP (без HTTPS) — и cookie сессии **специально не
помечена Secure**, когда соединение не HTTPS. Если бы она была всегда Secure,
вход с других ноутбуков/телефонов в зале по `http://` тихо ломался бы:
браузер бы отправлял пароль, сервер отвечал бы `200 OK` с cookie, но браузер
эту cookie бы не сохранял — и судья решил бы, что "сайт не пускает".

## Переезд на сервер

Поменять `DATABASE_URL` в `.env.local` на адрес серверной базы. Код не меняется.

## Docker и деплой на сервер

Тот же образ и пайплайн, что у `sezam_fullstack` / `artline-fullstack`:
`Dockerfile` собирает standalone-сборку Next.js, GitLab CI на `main`
собирает образ через kaniko, кладёт его в registry проекта и по ssh
поднимает `docker compose` на сервере. На всех ветках и MR перед этим
гоняются `npm run lint`, `npx tsc --noEmit`, `npm test`.

Локально (нужен `.env`, пример в `.env.example` — раздел Docker):

```bash
docker compose up -d --build       # http://localhost:3000
DATABASE_URL=mysql://fgc:<MYSQL_PASSWORD>@127.0.0.1:3307/fgc npx tsx scripts/create-admin.ts admin
```

`db/schema.sql` применяется автоматически при первом создании тома MySQL.
Миграции из `db/migrations/` на уже существующей базе — руками, как раньше:

```bash
docker compose exec -T db mysql -uroot -p"$MYSQL_ROOT_PASSWORD" fgc < db/migrations/<файл>.sql
```

Бэкап в Docker: `docker compose exec db mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction fgc > backups/fgc-$(date +%Y%m%d-%H%M%S).sql`.

**Сервер общий с artline-fullstack.** artline живёт в `/root`
(`/root/.env`, `/root/docker-compose.yml`, порты 8000/5672/15672), поэтому
FGC деплоится в `/root/fgc` под compose-проектом `fgc` с портами 3000 и 3307,
оба привязаны к `127.0.0.1`. Ничего не пересекается. Снаружи нужен nginx на
порт 3000 — подходит `web/setup-nginx-ssl.sh -t backend -o 3000` из artline.

Переменные CI/CD (Settings → CI/CD → Variables): `GIT_KEY` (File, ssh-ключ),
`USER`, `HOST`, `ENV` (File — продовый `.env` с
`MYSQL_ROOT_PASSWORD`, `MYSQL_PASSWORD`, `SESSION_SECRET`). Админа на сервере
создать той же командой `create-admin.ts` через ssh-туннель:
`ssh -L 3307:127.0.0.1:3307 root@<host>`.

## Порядок работы в день турнира

1. **Добавить команды** (`/admin`, минимум 9 — иначе не хватит для трёх альянсов
   на этапе выбора альянсов, минимум 6 — иначе не сгенерировать расписание).
2. **Сгенерировать расписание.** Пересоздать его можно сколько угодно раз —
   **но только пока ни один результат матча не сохранён.** Как только сохранён
   первый результат, кнопка «Сгенерировать» вернёт ошибку:
   ```
   409 — "Есть сыгранные матчи — расписание пересоздать нельзя"
   ```
   Это защита от случайной потери введённых результатов, а не баг.
3. **Вводить результаты по ходу игр** (`/admin/matches`).
4. **После квалификации — выбор альянсов** (`/admin/alliances`), затем
   **генерация плей-оффа** и ввод его результатов там же, в `/admin/matches`.
5. Итог виден на табло (`/`) сразу — оба раунда, квалификация и плей-офф,
   в одном списке матчей. Явной надписи "чемпион" на табло нет: победивший
   альянс — тот, что выигрывает 2 из 3 матчей плей-оффа, это видно по счёту
   в строках "ПО1/ПО2/ПО3".

## Правила, которые не проверяет программа

- **Один судья — один матч.** Конфликтов система не отслеживает: если два
  человека одновременно открыли один и тот же матч и оба нажали
  «Сохранить», молча победит тот, кто сохранил последним — второй судья
  никак не узнает, что его ввод перезаписан. Договоритесь заранее, кто
  вводит какой матч.
- **Зелёная галочка "✓ Сохранено" живёт только до следующей правки.**
  Если после сохранения изменить любое поле формы, галочка сразу пропадает —
  это не баг, а специально: галочка должна всегда означать «то, что сейчас
  сохранено в базе», а не «то, что я когда-то сохранял». Изменили —
  нажмите «Сохранить» ещё раз.
- **Выбор альянса капитаном другого альянса.** По регламенту капитан может
  выбрать капитана нижестоящего альянса — тот уходит к выбравшему, а его
  место занимает следующая свободная команда по рейтингу. **Это работает
  прямо в интерфейсе:** на `/admin/alliances` такие команды показываются в
  выпадающем списке с подписью `— captain of Alliance N`, а перед самим
  перехватом сайт спрашивает подтверждение и объясняет последствие.
  Забрать капитана можно только вниз по посеву, как и требует регламент.

## Проверка нагрузки

```bash
node scripts/load-test.mjs http://localhost:3000 100 20
```

Имитирует зрителей с телефонов (`/api/standings` раз в 10 с) и два экрана
проектора (оба эндпоинта раз в 3 с), печатает p50/p95/p99 и ошибки. Скрипт
только читает — запускать безопасно в любой момент. Замер 3 сентября на
ноутбуке: 500 зрителей → p95 = 16 мс, ошибок нет.

## Бэкап базы

Перед любым необратимым действием (Reset расписания, пересборка плей-оффа,
«Delete all» команд, очистка базы) сделайте снимок:

```bash
npm run backup      # backups/fgc-ГГГГММДД-ЧЧММСС.sql
```

Восстановление:

```bash
mysql -u root fgc < backups/fgc-20260905-141500.sql
```

Занимает секунду и один раз за турнир может спасти день. Папка `backups/`
не попадает в git.

## Если что-то пошло не так

- **Судья заблокирован после неверного пароля.** 5 неверных попыток входа
  подряд блокируют этот логин на 30 минут (проверено: 5 попыток → `401`,
  6-я → `429 "Слишком много попыток"`). Счётчик живёт в памяти процесса —
  **перезапуск сервера (`npm start`) снимает все блокировки мгновенно.**
  Это самый быстрый способ снять блокировку посреди турнира, если судья
  не хочет ждать 30 минут.
- **Что можно отменить/исправить, а что нет:**
  - Результат матча — можно ввести заново в любой момент, старое значение
    просто перезаписывается.
  - Расписание квалификации — можно пересоздать, только пока не сохранён ни
    один результат (см. выше). После первого сохранённого результата — нет.
  - Выбор альянсов — можно сбросить кнопкой «Сбросить выбор альянсов»
    (`/admin/alliances`) и начать заново.
  - Удаление команды — запрещено (`409`), если команда уже фигурирует хоть
    в одном матче расписания. Проверено: попытка удалить команду из
    сыгранного матча возвращает
    `409 — "Нельзя удалить команду — она уже участвует в расписании матчей"`.

## Несколько фолов в одном матче — как считается

Если альянсу засчитывают несколько фолов в одном матче, штраф считается
**один раз от суммы процентов**, а не по каждому фолу отдельно.

Основание — дословные формулировки мануала: MINOR FOUL это 5%, MAJOR FOUL
10% «от pre-penalty MATCH score», «Multiple FOULS assessed to a REGIONAL
ALLIANCE during a single MATCH are **cumulative**», а § 4.5 говорит «All
fractional MATCH scores round up to the nearest whole number». Про
округление каждого фола по отдельности мануал не говорит ничего, поэтому
проценты складываются от одной базы и округляются один раз.

Пример: доштрафной балл альянса 21, три незначительных фола против него →
`ceil(21 × 0.15) = ceil(3.15) = 4` очка сопернику (а не `ceil(21×0.05)×3 = 6`).
Смешанный случай: балл 33, один minor и один major → `ceil(33 × 0.15) = 5`.

Логика в `foulPenalty()` (`src/lib/scoring/match.ts`), закреплена тестами.
**Трактовку стоит проговорить с главным судьёй** — мануал про пофольное
округление молчит, это наше прочтение.
